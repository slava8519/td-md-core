# EAM-Al reference data (M6 PR-E2 / PR-E7)

Frozen external reference for the spline/setfl EAM path. Self-contained — the
comparison test (`Test_EAM_Spline`) reads the frozen numbers below and needs **no
LAMMPS at run time** (LAMMPS was used once to generate them; pattern mirrors
`reference_data/nist_lj/`).

## Potentials

| file | provenance |
|---|---|
| `Al_zhou.eam.alloy` | Real Al EAM, **Zhou et al., Acta Mater. 49, 4005 (2001)**; DYNAMO setfl, distributed with LAMMPS (`potentials/`). Nrho=Nr=10001, cutoff 10.1025 Å. Vendored verbatim with attribution for the physics cross-check. |
| `Al_small.eam.alloy` | Tiny **synthetic** setfl (N_rho=N_r=10) — a parser/indexing fixture only, "not a real potential". From the tdmd_V2 test fixtures. |

## Frozen 864-atom reference (`eam_al_864.*`)

Generated by `gen_reference.in` with LAMMPS (stable 22Jul2025):
perturbed 6×6×6 FCC-Al (864 atoms, a=4.05 Å), box 24.3 Å **> 2·cutoff = 20.205 Å**
so the orthogonal single-minimum-image convention is EXACT (matches `PairGeom`);
`displace_atoms ... random 0.12 ... 12345` breaks symmetry so forces are nonzero
(a non-vacuous check); `pair_style eam/alloy`, `run 0`.

| file | content |
|---|---|
| `eam_al_864.data`   | LAMMPS `write_data` (FP64 positions + box); read by `read_lammps_data`. |
| `eam_al_864.forces` | dump `id x y z fx fy fz` (`%.16e`, sorted by id) — the reference forces. |
| `eam_al_864.pe`     | total potential energy, full precision: **−3065.71779127815 eV**. |
| `gen_reference.in`  | the LAMMPS input that produced all of the above (reproducible). |

## What it validates

`Test_EAM_Spline` reads `eam_al_864.data` + `Al_zhou.eam.alloy`, builds our
LAMMPS-replica cubic spline (`EamSetfl::from_setfl`), computes EAM energy+forces
via `eam_direct_fp64`, and compares to the frozen LAMMPS numbers at
**print-tolerance**. This closes the gap FD self-consistency cannot see: that the
**setfl reader + spline interpolation** are correct against a real Al potential
and a reference implementation. (Bit-for-bit vs LAMMPS is NOT claimed — that
would need replicating LAMMPS's exact eval order; our bitwise contract is
CPU↔GPU / 1-vs-z internally. M6_EAM_MANYBODY_DESIGN §7 [RISK].)
