# W-КОНТРАКТ: донационные батчи как материальная w-фаза
## TD-MD Core · v1.0 · 2026-07-03 · весь документ — [ENG]

Нормативный контракт W-трека (лестница `_meta/AUDIT_W_PHASE_NEIGHBORS_2026-07-02.md` §5).
Статус реализации: примитивы — PR-0a (`738893f`); сериальный донационный оракул EAM — PR-1
(этот документ приземлён им же). Дизайны: `_meta/PR0A_WCONTRACT_DESIGN_2026-07-02.md`,
`_meta/PR1_DONATION_ORACLE_DESIGN_2026-07-02.md`. Потребитель формулировок — PR-2
(тредовое кольцо) и далее M5b.

## §1. Идея

**W-фаза = донационные int64-батчи при событиях ко-резидентности зон (CoRes); C-фаза =
достройка.** Обобщение диссертационного w-scatter с сил на любой B1-накопляемый пасс
дескриптора: пока зона ждёт своего расчёта, соседние резидентные зоны *дарят* ей
int64-вклады (для EAM — в плотность ρ), и к моменту её финализации плотность уже собрана.
«Уточнение» — в диссертационном смысле **точного досуммирования** недостающих слагаемых:
никакого predictor/corrector, экстраполяции или пересчёта в контракте НЕТ (см. аудит §2.1 —
в первоисточнике их тоже нет). Донор при этом легально находится в состоянии d/w —
[ENG]-перепланировка диссертационного донора (см. аддендум к `ZoneFSM` §10).

Что это удаляет (диагноз аудита §1): пооконный 3-зонный пересчёт плотности исполняет
intra-пары ×3 и cross-пары ×2 за проход; донации исполняют каждую пару **ровно один раз**.

## §2. Нормативное расписание

Единый источник истины — `donation_layout(j, n, pbc)` (`eam_zone.hpp`; PR-0a): батчи
позиции j = self-слоты + cross-рёбра, исполняемые ДО finalize(j). Свойства (зубы —
`Test_W_Contract` T4/T5/T5b/T-SIM/T8):

| Батч | ready (событие) | deadline (первый читатель) |
|---|---|---|
| self(k) | фронт false→true `ensure_drift(k)` прохода h | finalize(k); pbc k≤1 — finalize(1)/хвост |
| cross(k,k+1), k≤n−2 | CoRes(k,k+1): оба слота present ∧ drifted | finalize(k) |
| **шов cross(n−1,0)** (pbc) | CoRes(n−1,0) = прибытие ПОСЛЕДНЕЙ зоны (ready=n−2) | **СТРОГО ДО finalize(n−1)**, который идёт in-scan |

- Инвариант: emit == ready для всех батчей, КРОМЕ шва (emit = deadline = n−1). Вариант
  «шов в хвосте прохода» опровергнут верификатором аудита и физикой (зуб Т-6 PR-1:
  поздний шов расходится побитово на owned(n−1)) — не воскрешать.
- **Слот- vs метка-пространство:** расписание — в слот-пространстве прохода;
  `label = slot_zone_id(pass_rotation(h,n,pbc), slot, n)` (`eam_zone.hpp`). ВСЕ
  персистентные структуры (ρ-аккумуляторы, леджер, будущие CSR/эпохи/device-зеркала)
  ключуются **по zone_id**, не по слоту. Зуб PR-2 — PBC-прогон ≥2 полных оборотов, n≥5,
  побитово.
- **Edge-порядок `close_cross_batch`** (место ручной ошибки): аргументы — по КОНЦАМ РЕБРА:
  первая маска — зона, чья ВЕРХНЯЯ граница есть ребро (получает CrossHi), вторая — верхний
  сосед (CrossLo). Шов `donate_cross(n−1, 0)`: CrossHi → n−1, CrossLo → 0. Числовая
  сортировка инвертировала бы роли (want-mask assert само-ловит, но конвенция названа).

## §3. Леммы (с честными границами)

- **W-1 (B1-сплит):** для любого разбиения мультимножества вкладов на батчи и любого
  порядка их исполнения сырой int64 равен монолитной сумме. Условия: те же double-входы
  (после идемпотентного drift), тот же `PairGeom::reduce` / `eval_rhoa` / fb-формат.
  Лемма негации: направленный обход пары даёт точные IEEE-негации разностей (round нечётен
  в min-image) ⇒ r2 побитово равен с обеих сторон ⇒ «один v в оба конца» воспроизводит
  мультисет направленного обхода. Исполнимый свидетель — зуб Т-9 (G-ORDER).
- **L-CLOSE (бит-финальность чтений):** halo-сосед, читаемый силовым пассом finalize(j),
  лежит в rcut от слэба j; его доноры — в 2·rcut ⇒ резидентны; недонированное ребро
  (j+1,j+2) вносит ему **литеральный ноль** (открытый cutoff r²<rc² — не квантованный +0).
  **LOAD-BEARING предпосылка — страж `membership_ok` c g = 0.5·(width − 2·rcut)**
  (`eam_ring.hpp`; сериальный близнец — `check_donation_residence`, `eam_donation.hpp`).
  **ИЗМЕРЕНО (PR-1, класс-3):** за пределами стража, на полосе дрейфа (g_eam, g_pair],
  пути НЕ «одинаково усечены» — персистентная ρ читаемого halo СТРОЖЕ-ПОЛНЕЕ оконной
  (держит уже-донированные вне-оконные смежные рёбра) ⇒ **g_eam несущий для самой
  эквивалентности G-A**, не только для стабильности чтений. PBC-индукция — в
  слот-пространстве. Зубы: Т-11 (пять измерений D7).
- **Честная граница леджера:** леджер видит ЦЕЛЫЕ батчи; пара, молча выпавшая ВНУТРИ
  батча, невидима и ему, и 1-vs-z, и run-to-run ⇒ независимые FP64-оракулы
  (`eam_direct_fp64`, класс MB2) — непереуступаемые свидетели каждого PR (зуб Т-7).

## §4. Дескриптор

`WClass`/`donor_roles` (PassDecl, `many_body.hpp`) + `validate_pass_decls`: kAccumB1 ⇒
`accum_fracbits>0`, запрещён на BondOrder (ζ-класс FP-редукции), roles только на kAccumB1,
kReserved3 запрещён, iterative ⇒ kCOnly. **Честная оговорка (дословно из кода, не
переформулировать):** машинная проверка ловит ТОЛЬКО ζ-класс; canon-dependent-addend-класс
(int64-лейны MEAM, чьи double-адденды зависят от S_ij=Π_k до квантования) машинно НЕ
ловится — свидетели только состязательный дизайн классифицирующего PR + FP64-оракул.
**fb-ловушка:** формат аккумулятора ключуется ТОЛЬКО от рантаймового
`density_fracbits()` (44=Q19.44 / 40=Q23.40), НИКОГДА от статического
`accum_fracbits` дескриптора (тот — документация; зуб Т-12).

## §5. Леджер полноты

Раскладка — `closure_bit(pass, role)` (uint32 = 4 роли × ≤8 пассов; расширение
INV-3-леджера `contrib_mask`). Want-сторона — `want_closure_mask(passes, j, n, pbc)`
(рёбра отпадают на free-краях зеркально `eam_window_layout`). Правила:
- **Вакуумный батч:** бит = «батч ИСПОЛНЕН (возможно, вакуумно)», НЕ «внёс ≥1 пару».
  Пустая зона ставит биты — иначе END голодает (зуб Т-14).
- **Pass-scoped:** аккумуляторы и леджер сбрасываются на RECV (PR-2) / `reset_pass`
  (serial); mid-pass HALT отбрасывает проход ЦЕЛИКОМ; частичный реплей батчей ЗАПРЕЩЁН
  (API для него не существует намеренно).
- **Разграничение (PR-2 не смешивать):** want-set ПЛАНИРОВАНИЯ finalize(j) — самости всех
  оконных слотов + внутренние рёбра (закрывается deadline-планированием, зубы T8/T-SIM);
  `want_closure_mask(j)` — БУХГАЛТЕРИЯ END самой зоны j (только её роли).
- **Точка проверки PR-2:** непосредственно перед `ZoneFSM::apply(END)`.

## §6. Скоуп донаций

Донации двигают ТОЛЬКО density-пасс. PE (φ-once по глобальному key + F(ρ) на owned),
min_r2, вириал — остаются в силовом пассе C-фазы ДОСЛОВНО. При будущем раздвоении
force-пасса это условие пере-специфицировать.

## §7. rho_cap / G-HALT-ATTR

Донированный путь проверяет cap ТОЛЬКО на owned-атомах, на их ПОЛНОЙ ρ, в их finalize
(оракул проверяет каждый оконный атом на ЧАСТИЧНОЙ оконной ρ). **Эквивалентность
trigger-set на гранулярности прохода** (= {∃ атом: полная ρ > cap}) опирается на
**D3: ρ_a(r) ≥ 0** ⇒ квант ≥ 0 ⇒ частичные суммы монотонно неубывают ⇒ partial ≤ full:
нет ни ложных, ни пропущенных HALT (зуб Т-10). D3 — load-time стражи: точный минимум
кубиков сплайна (`EamSetfl::assert_rhoa_nonnegative_`; проверка одних узлов НЕДОСТАТОЧНА —
межузловой овершут, зуб Т-15б) + замкнутая форма для аналитики (β>0 ∧ rho_amp>0).
**Атрибуция:** различие старый-vs-новый легитимно и НЕ гейтится; атрибуция нового пути
детерминированно-пер-зонная (owner) — гейтится сообщением. В кольце — throw →
`set_halt(Halt::Internal)`, как сегодня.

## §8. Домен G-A (побитовый гейт «донированный ≡ оракул»)

Сравниваются: силы ВСЕХ атомов (пишутся owned-only, ровно раз), PE, min_r2, сырой int64
ρ **OWNED**-атомов. **Halo-ρ в персистентных аккумуляторах ЛЕГИТИМНО расходится** с
оконной локальной ρ (персистент держит рёбра, которых окно {j−1,j,j+1} не видело — напр.
(j−2,j−1)); **полный memcmp ρ-массивов — ЛОЖНО-КРАСНЫЙ и ЗАПРЕЩЁН как гейт.**

## §9. РЕШЕНИЕ §8.1 аудита: ARRIVAL-вариант

> **W-РАСПИСАНИЕ.** (i) Батчи позиции j — `donation_layout(j,n,pbc)`; внутри позиции self,
> затем cross (соглашение; наблюдательно невидимо по W-1). (ii) **READY:** self(k) — фронт
> false→true `ensure_drift(k)` прохода h (НЕ «на RECV»: dt приезжает с arrival 0, drift
> ленивый); cross(a,b) — CoRes(a,b): оба слота present ∧ drifted. Донации идут по
> ПРОДРЕЙФОВАННЫМ координатам. Донор НЕ обязан быть в состоянии c: материальные вклады
> легальны из d/w. (iii) **DEADLINE:** все батчи позиции j — СТРОГО ДО finalize(j)
> (fin_pos(j)=j, кроме pbc j=0 → хвост); шов — СТРОГО ДО finalize(n−1). (iv) **СВОБОДА:**
> в [READY, DEADLINE] исполнитель волен выбирать момент и порядок; побитовость не зависит
> от выбора (W-1) ПРИ предпосылке L-CLOSE (страж g). (v) **НОРМАТИВНАЯ ТОЧКА —
> arrival-событие:** PR-2 планирует донации самостоятельным шагом scan-цикла между
> arrival/drift и finalize, НЕ зашивает в тело finalize. Альтернатива «внутри finalize(k−1)
> после START» (диссертационная буква) W-1-эквивалентна — отвергнута ради M5b
> (донации = полезная работа при ожидании апстрима; try_recv-планировщик).

Serial-исполнение склеивает оба кандидата ⇒ тесты PR-1 к выбору слепы; PR-2 связывает
ФОРМУЛИРОВКА (не тест). Исполнимый свидетель свободы (iv) — зуб Т-9.

## §11. Что НЕ делать

- Не строить interior/frontier координатный предикат в силовом пути (L-CLOSE решает
  чтение точным cutoff-тестом).
- Не вводить второй тип сообщений / транзит ρ в ZoneMsg (B5 «зона пакуется ровно один
  раз» нетронут — пер-узловое пассовое состояние).
- END/SEND, батчированный END-sync и позиционная Λ-цепочка не переставляются.
- Никаких глобальных редукций.
- Single-GPU выигрыш обязан быть УДАЛЕНИЕМ работы, не перекрытием (кольцо 99%
  kernel-bound); донационная density GPU — PR-3b с пре-регистрацией **R_W ≥ 1.15** и
  откатом при NULL.
